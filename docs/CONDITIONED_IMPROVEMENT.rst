1200 RPM 실패 원인·조건별 개선·새 원본 기록 검증
=============================================

2026-11-04. 정상 기준을 운전 조건별로 분리하고 추가 정상 데이터를 수집했습니다.
새 원본 기록 시험 정답률은 보류를 포함해 51.88%, 정상 이상 표시율은 2.5%였습니다.
고장 종류 정답률은 48.21%로 자동 확정용 성능에는 부족합니다. 운영 사용은 승인하지 않습니다.

무엇이 실패했는가
-----------------

이전 CrossSpeed 1200 RPM 시험에서 정상 점수 중앙값 4.360은 고정 이상 경계
2.386을 넘었고, 정상 399창 모두가 이상으로 표시됐습니다. 채널 1과 다른 채널의
1X 에너지 비율이 정상 top-5 변화 목록에 반복됐습니다.

확인된 구현/모델 한계는 다음과 같습니다.

* 600/900 RPM 정상 분포를 하나의 기준으로 합쳐, 정상 기준이 없는 1200 RPM까지
  적용하려 했습니다. 회전 차수로 표시한다고 전달 경로·공진·방향별 응답이 같아지지는 않습니다.
* 동일 1X 분모를 쓰는 여러 비율이 상관된 변화를 중복 반영했습니다.
* 고장 종류를 한 개 중심으로 요약하면 속도·강도별로 다른 고장 형태를 포괄하기 어렵습니다.
* 새로운 자료에는 서로 다른 샘플링률도 존재해, Nyquist와 분석 대역을 통일하지 않은
  전체 대역 에너지 비율을 직접 비교하면 추가적인 차이가 생깁니다.

특정 공진·센서 결함 하나를 물리 원인으로 확정한 것은 아닙니다. 원본에는 창별 실측
타코미터나 현장 설치 이력이 없습니다. 확인한 사실은 운전 조건별 정상 특징 분포의 불일치입니다.

구현한 개선
-----------

vibration/conditioned.py:

* fit_conditioned: RPM별 정상 중심/robust scale, 별도 정상 보정, 고장 기록별 prototype 적합.
* ConditionedDiagnostic: 해당 RPM 기준을 조회한 뒤 정상/보류/고장 후보/종류 불명을 반환.
* 기준 없는 속도의 외삽은 금지합니다. 범위를 벗어나면 normal_reference_speed_unavailable로 보류합니다.
* 보간은 명시적으로 켠 경우에만 제한된 간격에서 허용합니다. 최종 채택 모델은 보간을 끄고
  실제 해당 RPM의 추가 정상 기록을 사용했습니다.
* 고장 기록별 중심을 유지하고, 다른 학습 기록과의 거리로 종류 거부 한계를 구했습니다.
  후보가 정확히 동률이면 margin 설정이 0이어도 강제 분류하지 않습니다.
* levels_orders는 채널별 log RMS와 0.5/1/2/3/4/5/6/8/10X 에너지의 10개 특징을 사용합니다.
  기존 비율 특징 조합과 함께 개발 자료에서 비교했습니다.

canonical_values는 anti-alias 필터를 포함해 8/16 kHz를 공통 4 kHz 분석률로 맞춥니다.
이 변환은 해당 분류기의 공통 대역용이며, 기존 원시 파형/FFT/고주파 엔벨로프 모듈을
대체하거나 원본 데이터를 덮어쓰지 않습니다. 시험에서는 비중복 2초 창을 사용했습니다.

ConditionedStage, ModelRegistry.use_conditioned, classify_window에 연결했습니다.
단위/장비/운전 계열/채널/창 길이와 입력 샘플링률을 검사하고, 창 내 RPM 변화가 크면 보류합니다.
같은 속도에서도 부하·설치·센서가 바뀐다면 별도 condition_id/교정·설치 식별자로 기준을 구분해야 합니다.

기존 실패 자료에서의 개발 확인
-----------------------------

개봉한 CrossSpeed 1200 RPM은 이번에 개발 자료로 명시했습니다. 기존 최종 시험을
다시 새 독립 시험이라고 부르지 않았고 원래 시험 로그도 보존했습니다.

속도별 정상 적합 11개 취득, 정상 보정 3개 취득, 나머지 정상과 고장 취득을 개발 평가로
분리했습니다. 상대 특징을 사용한 조건별 모델의 전체 개발 평가 1039창 정답률은 93.55%였습니다.
그중 1200 RPM 평가 340창/17개 취득에서 정상 120창의 이상 표시가 6개(5%)였습니다.
동일 정상 부분집합은 이전 통합 모델에서는 모두 이상으로 표시됐습니다.
이는 해당 RPM 정상 기준을 추가한 효과의 개발 확인이며 새로운 맹검 성능이 아닙니다.

새 자료 수집 및 정상 기준
-----------------------

새 데이터는 서울시립대 MOCHU 6204 시험대 자료입니다.
Seongjae Lee, Taewan Kim, Taehyoun Kim.
Dataset DOI 10.17632/53vtnjy6c6.1, CC BY 4.0.
https://data.mendeley.com/datasets/53vtnjy6c6/1
제공자 논문: DOI 10.1016/j.dib.2024.110940,
https://pmc.ncbi.nlm.nih.gov/articles/PMC11437749/

총 54개 원본 MAT, 1,039,840,124 bytes(약 1.04 GB)를 추가 수집하고 제공자 SHA256을 검사했습니다.

* 16 kHz 파일 48개: 600/800/1000/1200/1400/1600 RPM별 정상, 헐거움,
  정렬불량 3강도, 불평형 3강도. 베어링 정상 조합만 선택했습니다.
* 추가 8 kHz 정상 6개: 같은 여섯 RPM의 원본 정상 기록.
* 원본 Data는 1,280,000점/단일 채널이며 제공자는 단위를 g로 명시합니다.
  16 kHz는 80초, 8 kHz는 160초입니다. 별도 센서 교정 증명은 제공되지 않았습니다.
* 정상 자료는 총 12개 기록/1440초. 이 중 최종 정상 16 kHz/1200 RPM의 80초는
  학습·보정·후보 선택에 쓰지 않았습니다.

처음에는 다른 속도의 정상 기준을 보간하는 후보를 개발 자료에서 비교했으나 성능이
부족해 새 시험을 열지 않았습니다. 이후 같은 RPM의 추가 정상 기록과 공통 대역을 확보했습니다.
최종 모델은 별도 8 kHz/1200 RPM 정상 기록을 기준으로 사용합니다.
따라서 이번 시험은 정상 기준 없이 미관측 속도를 맞히는 시험이 아닙니다.

학습/조정과 새 시험의 분리
-------------------------

새 최종 시험은 처음부터 16 kHz/1200 RPM 원본 8개 전체로 지정했습니다.
다른 샘플링률의 정상 기록을 추가하면서도 그 8개 파일은 열지 않았습니다.
원본의 인접 창을 섞는 무작위 train/test 분할은 하지 않았습니다.

후보 선택은 개발용 16 kHz/1000 RPM 원본 8개에서 했습니다.
동일 RPM 정상 기준과 공통 대역을 사용한 6개 후보 중, 개발 Macro-F1과 판단 비율로 선택했습니다.
선택 전제는 정상 이상 표시 <=5%, 정상 수용 >=50%, 고장 감지 >=50%, 판단 비율 >=50%였습니다.
이것은 시험 개봉 전 sanity check이며 현장 합격 기준이 아닙니다.
선택 후보의 개발 정답률은 90.94%, 정상 이상 표시율은 2.5%였습니다.

그 뒤 46개 source 원본을 사용해 최종 적합했습니다.

* 정상 기준: 8 kHz 정상 6개와 16 kHz 비시험 정상 4개 = 10개 원본/640창.
* 정상 보정: 16 kHz/800 RPM 정상 원본 1개/40창. 정상 중심 적합에 넣지 않았습니다.
* 고장 학습: 16 kHz 비시험 고장 원본 35개/1400창.
* 모델: levels_orders, 최소 후보 차이 0, 수치 동률은 보류, 보간/외삽 없음.
* 1200 RPM 정상 기준은 8 kHz 원본이며, 최종 시험의 16 kHz 정상 파일은 사용하지 않았습니다.

새 모델과 전체 vibration Python 파일, 평가 코드, 기록 계획의 SHA256을 시험 전에 고정했습니다.
고정 모델 SHA256: 4ebdd4393b4267eae4013b3ef649384624617defcb827e4d93f0652f8dc33ecd

2.5%를 현장 오경보율의 보증으로 해석하면 안 됩니다. 실제 경보 지속시간/운영 정책의
경보 발생률도 이 창별 진단 표지만으로 검증한 것이 아닙니다.

독립성 및 변경 방지 감사
-----------------------

최종 8개 파일의 원시 Data 해시는 source 46개 및 다른 시험 파일과 중복되지 않았습니다.
원본 파일/창 위치를 재집계해 8개 접근, 320개 예측에 중복·누락이 없음을 확인했습니다.
전체 모델·코드·기록 계획 해시도 시험 전과 같았습니다.

제공자는 서로 다른 샘플링률에서 각각 수집했다고 설명합니다. 다만 재설치/세션 식별자는
없어 원본 기록 분리 이상을 단정하지 않았습니다. 다른 샘플링률이 같은 파형을 재사용한
경우를 추가 검사했습니다. source 다섯 속도의 잡음 상세 최대 상관도는 0.064~0.131,
최종 정상 1200 RPM은 0.129였습니다. 사전 기준 0.98 미만이며 정확한 Data 복제도 없었습니다.
이 검사는 동일/재표본화 파형 중복을 찾는 보조 검사이지 독립 설치의 증명이 아닙니다.

정리하면 이번 결과는 같은 시험대의 정상 기준을 확보한 원본 기록/샘플링 도메인 분리 검증입니다.
새 산업 설비 무학습 적용 또는 320회의 독립 현장 고장 시험이 아닙니다.
이전 CrossSpeed의 11.04%와 데이터·채널·고장 종류가 달라 단순 상승폭으로 비교할 수 없습니다.
새 시험 이후 모델·특징·임계값을 재조정하지 않았습니다.

API 및 운영 판단
---------------

::

   import json
   from pathlib import Path
   from vibration import ConditionedDiagnostic, ConditionedStage
   from vibration import VibrationAnalyzer, AnalysisConfig, SignalBlock

   profile = json.loads(Path('output/condition_improvement/matched_frozen.json')
                        .read_text(encoding='utf-8'))
   model = ConditionedDiagnostic(profile)
   # raw: 동일 장비/단위의 32000 x 1, 16 kHz, 2초 입력.
   scope = {'asset_id': 'UOS_MOCHU6204', 'condition_id': 'steady_bearing_healthy', 'unit': 'g'}
   result = model.analyze(raw, 16000, 1200, scope=scope, channel_names=['radial_vibration'])

fit_conditioned와 ConditionedStage가 서버/DB 없이 동작하며,
ModelRegistry.use_conditioned(profile), Storage.save/load에도 연결했습니다.
실제 source 원본 2개에서 순수 API, VibrationAnalyzer 단계, 레지스트리,
DB 저장/복원, 실제 재생 작업자의 결과가 일치했습니다. 시험 파일은 재개봉하지 않았습니다.

기능 회귀 534개(81+58+32+363)와 휠 격리 실행도 통과했습니다.
이는 예측 성능 합격을 뜻하지 않습니다. 새 정상 기준 처리와 이상 후보 감시는 개선했지만
고장 종류 자동 확정에는 부족해 operational_use=False를 유지하고 기본 모델로 활성화하지 않았습니다.
추가 개선 시 이번 시험 자료는 이미 개봉한 개발 참고 자료가 되며 새 최종 시험이 필요합니다.
