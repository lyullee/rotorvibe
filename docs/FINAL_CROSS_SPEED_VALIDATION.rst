1200 RPM 최종 독립 시험 결과: 교차속도 적용 불가
==============================================

2026-11-04. 정상 우선 진단 API의 교차속도 시험용 후보를 고정한 뒤,
보존했던 1200 RPM 1178개 창/59개 취득 기록을 처음으로 수치 평가했습니다.
전체 정답률은 11.04%, 정상 오경보율은 100%였습니다.
이 후보는 운영에 사용할 수 없습니다. 기존 600/900 RPM 모델의 범위와 파일은 유지했습니다.

무엇을 검증했는가
----------------

이전 93.74%는 해당 시험대의 속도별 모델을 학습 외 600/900 RPM 취득 기록으로
검증한 결과였습니다. 해당 모델은 condition_id와 RPM 범위가 속도별로 제한되어
1200 RPM에 적용하면 전부 범위 밖으로 보류합니다. 그 범위를 임의로 넓혀 기존
모델의 검증이라고 주장하지 않았습니다.

별도 교차속도 후보를 다음과 같이 만들었습니다.

* 학습: 제공자 source_train 1888창, 관측 속도 600/900 RPM만 사용.
* 정상 기준: 531창. 정상 보정: 80창/4개 취득. 고장 학습: 1277창.
* 기존 속도별 모델에서 사용한 정상 보정 취득 그룹을 그대로 유지.
* relative 128개 특징, 정상 수용 80%/이상 경계 99% 분위수, 후보 차이 0.10,
  가우시안 분산 하한 0.25. 이 수치와 특징은 최종 시험 전에 고정.
* 두 속도의 정상 기준과 고장 특징을 함께 적합. steady_cross_speed_qualification이라는
  명시적 운전 계열을 선언하고, 시험 예정 범위 570~1260 RPM을 설정.
  1200 RPM은 검증 전에는 미관측 적격성 평가 범위이며 지원 완료 범위가 아니었습니다.
* 속도별 condition_id를 위 운전 계열로 매핑하는 규칙은 장비·단위·RPM·채널만 사용.
  고장 라벨·파일명·취득 번호로 특징이나 예측을 바꾸지 않았습니다.

1200 RPM의 정상 자료 399개도 적합·정규화·임계값 보정에 사용하지 않았습니다.
동일 후보를 고정한 뒤 source_validation과 최종 시험을 평가했으며 결과를 보고
다른 후보를 선택하거나 설정을 바꾸지 않았습니다.

실패 원인에서 확인된 부분
------------------------

동일한 고정 정상 이탈 점수의 분포가 크게 달라졌습니다.

* 이상 경계: 2.38625. 정상 수용 경계: 2.13019.
* 600/900 RPM 검증 정상: 중앙값 1.21264, 최대 2.01601.
* 1200 RPM 최종 정상: 최소 3.49317, 중앙값 4.36006, 최대 6.14896.

1200 RPM 정상은 단 한 창도 학습 정상 기준의 이상 경계 안에 들어오지 않았습니다.
정상 top-5 변화 목록에는 채널 1과 채널 2/3/4의 1X 에너지 비율이 399창 모두에
포함됐습니다. 회전 차수·비율 특징만으로 속도 조건에 따른 특징 분포 차이를 제거하지
못했다는 관측입니다. 특정 공진·설치 변화·센서 문제를 확정한 것은 아닙니다.
원본에는 창별 실측 타코미터가 없고 진폭 교정 단위도 확정되지 않았습니다.

종류 보류 1048개는 모두 학습 고장 특징 거리 한계를 넘었습니다.
그중 127개는 후보 간 차이도 작았습니다. 보류 기능은 작동했지만
정상 이탈을 고장 징후와 구분할 기준이 1200 RPM을 포괄하지 못했습니다.

처리 및 다음 검증 조건
---------------------

교차속도 후보의 운영 사용은 거부합니다. 운영 모델로 등록/활성화하지 않았고
기존 속도별 범위를 넓히지 않았습니다. 속도별 모델도 제한된 벤치 검증 수준입니다.

1200 RPM에서 쓰려면 별도 취득한 정상 기준과 보정 기록을 확보하거나, 충분한
속도·부하 자료로 조건별 정상 분포를 모델링한 뒤 새 취득 기록으로 평가해야 합니다.
이번 최종 정상 399개를 학습한 뒤 같은 시험 성능을 새 독립 성능이라고 주장할 수 없습니다.
이번 자료는 이제 개봉한 시험 자료이며 결과에 맞춰 개선할 경우 새 최종 시험이 필요합니다.
기존 자료와 예측·모델·절차는 재현을 위해 보존했습니다.

기능 회귀시험 520개(67+58+32+363)는 다시 통과했습니다.
이는 계산/API 연결의 검증이며 이번 예측 성능 실패를 상쇄하지 않습니다.
